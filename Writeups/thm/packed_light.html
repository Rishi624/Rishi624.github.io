// Given Challenge

Analyze the provided PCAP and identify the covert communication channel. Recover the hidden data, decode it and obtain the flag.

The challenge looked like a normal PCAP analysis challenge, but the description already contained useful hints. It mentioned that packets were being sent every second, request headers looked suspicious, and something related to cryptography was involved.

Instead of randomly looking through packets, I decided to follow the hints given in the description.

// Step 1 - Inspect the Network Traffic

After opening the PCAP in Wireshark, I first checked which protocols were present. Since the description mentioned request headers, I suspected HTTP traffic.

Using the filter below showed communication over port 8080.

tcp.port == 8080

The packets appeared at regular intervals, almost exactly one second apart, matching the behaviour described in the challenge.

// Step 2 - Follow the TCP Stream

I right-clicked one of the HTTP packets and selected Follow → TCP Stream.

Instead of finding the flag, I found something much more useful: a Python script being downloaded from the server.

Initially I thought this script might contain the flag directly, but after reading it carefully I realised it was actually malware responsible for stealing the victim's keystrokes.

// Step 3 - Reverse Engineering the Script

The script contained several important pieces of information:

C2_URL = "http://byte-lotus-hotel.thm:8080/"

This confirmed where the stolen information was being sent.

The next important function was:

def getkey(): p1 = "H03lSt@ff0Nly!" p2 = "K3ep5cr3t!" return p1 + p2

This revealed the XOR encryption key used before transmitting every character.

Another important function showed exactly how the data was hidden:

raw_bytes = character.encode("utf-8") encrypted = xor(raw_bytes, getkey().encode()) b64_string = base64.b64encode(encrypted).decode() headers = { "Cookie": f"hotel_sess_state={b64_string}" }

This explained the complete process:

Keystroke ↓ UTF-8 Encode ↓ XOR Encryption ↓ Base64 Encoding ↓ Stored inside the HTTP Cookie header

This also answered the challenge objective of identifying the covert communication channel. The malware was hiding every keystroke inside the Cookie header rather than the request body.

// Step 4 - Extracting the Data

Using the HTTP request packets, I extracted every value of:

hotel_sess_state=encoded text

Each request contained only one encrypted character.

My first mistake was trying to decode everything together as one large Base64 string. That produced meaningless output because every keystroke had been encrypted separately.

After re-reading the Python code, I noticed that the XOR function was called once for each character, meaning every Base64 value also had to be decoded individually.

// Step 5 - Decoding

I used CyberChef to reverse the encoding process.

From Base64 ↓ XOR XOR Key: H03lSt@ff0Nly!K3ep5cr3t!

Doing this for each Cookie value revealed one plaintext character at a time.

Another mistake I made was getting two invalid characters during decoding. Initially I thought my XOR process was wrong, but every other character decoded correctly.

After checking the packets again, I realised I have misunderstood O's as 0's. Correcting the values fixed the problem immediately.

// Result

After decoding every encrypted keystroke and reconstructing the message, I recovered the challenge flag.

THM{V3r4_1s_w4tch1ng_0veR_y0u}
